Pi Observational Memory is a pi coding agent extension that gives your sessions persistent, structured memory without any manual summarisation. Parallel observer subprocesses distill raw conversation chunks into atomic observations stored in a branch-local ledger; a consolidator promotes the oldest observations into durable per-session topic files that survive context resets and `/tree` navigation.

## What it does

Observational memory solves the context-window problem for long-running pi sessions. As your conversation grows, the extension automatically:

1. **Observes** — cuts the raw conversation history into fixed-token chunks and fires parallel subprocess observers, each producing a batch of single-line atomic observations.
2. **Records** — commits each observation batch to a branch-local ledger so memory stays correct when you branch or rewind with `/tree`.
3. **Compacts** — when context pressure crosses a threshold, renders the active observation buffer plus your long-term memory map into a deterministic, model-free compaction block.
4. **Consolidates** — when the observation pool grows large, a consolidator subprocess promotes the oldest observations into durable `.memory/<sessionId>/` topic files and updates a running `JOURNEY.md` narrative for orientation.

<Note>
  The extension ships in the global extensions folder and is **gated off by default**. Use `/om on` to enable it for any session. State persists per session in the ledger and survives resume.
</Note>

## Key features

<CardGroup cols={2}>
  <Card title="Branch-Correct Memory" icon="code-branch">
    All short-term observations are stored in a branch-local ledger, so navigating with `/tree` rolls back memory to the right point automatically.
  </Card>
  <Card title="Parallel Observers" icon="bolt">
    Up to `observerConcurrency` (default 4) observer subprocesses run simultaneously — each is an independently inspectable recorded pi session.
  </Card>
  <Card title="Durable Long-Term Files" icon="file-lines">
    Topic files under `.memory/<sessionId>/` are not rolled back by `/tree`. Forks inherit their parent's memory on first touch.
  </Card>
  <Card title="Cost Tracking" icon="dollar-sign">
    Every worker's spend is captured from pi's built-in metrics and surfaced in the footer gauge and `/om:status` — real money spent never decreases under `/tree`.
  </Card>
</CardGroup>

## Quick commands

| Command | Effect |
|---|---|
| `/om` | Toggle observational memory on/off for this session |
| `/om on` / `/om off` | Set the gate explicitly |
| `/om:status` | Show workers, buffer, clocks, cost, topic files, journey size |
| `/om:compact` | Force a compaction immediately |
| `/om:consolidate` | Force a consolidation immediately |

<Steps>
  <Step title="Install the extension">
    Clone the repository into your pi global extensions folder so pi picks it up on every session start.
  </Step>
  <Step title="Enable for your session">
    Run `/om on` inside any pi session. The extension is invisible until you turn it on.
  </Step>
  <Step title="Work normally">
    Continue your session as usual. Observers fire automatically every `chunkTokens` of new history.
  </Step>
  <Step title="Inspect memory">
    Run `/om:status` at any time to see the active buffer, in-flight workers, topic file count, and session cost.
  </Step>
</Steps>
